# Workflow: Incident Response

## Trigger

Use when availability, correctness, data freshness, security posture, or access is degraded.

## Agents

- `incident-commander`
- `sre-engineer`
- `observability-engineer`
- domain responders
- `security-architect` for suspected security events

## Steps

1. Establish severity, impact, timeline, and responders.
2. Stabilize with reversible mitigations where possible.
3. Record observations, commands, decisions, and timestamps.
4. Validate restoration.
5. Create incident report and follow-up backlog.
6. Update runbook, alerts, skills, or templates when gaps are found.

## Outputs

- incident report
- follow-up backlog items
- updated runbooks or observability notes
