# Процесс: подготовка ML-системы

## Когда применять

Для ML-исследований с перспективой production, обслуживания прогнозов, конвейеров признаков, систем RAG и проверок перед приёмкой. Выбирайте подходящие шаги, не требуя полного выпуска для каждого эксперимента.

## Роли по необходимости

- ml-research-engineer для гипотез, разбиений и базовых вариантов
- ml-engineer для реализации модели и сервиса прогнозирования
- model-evaluation-engineer для сопоставимых подтверждений и анализа ошибок
- mlops-engineer для совместимости релиза, наблюдения и восстановления
- feature-store-engineer, когда важны доступность признаков и совпадение значений при применении

## Шаги

1. Определите решение, единицу прогноза, авторитетные данные или корпус, доступность целевых значений, базовый вариант, порог, стоимость значимых ошибок и целевую совокупность при применении.
2. Зафиксируйте условия оценки до настройки: версии данных и эталонов, временные границы или разделение сущностей, обучение преобразований только на тренировочных данных и нетронутую финальную отложенную выборку. Выбирайте разбиение под заявленный сценарий применения.
3. Реализуйте согласованное изменение модели, признаков или поиска. Для признаков используйте информацию, доступную на момент прогноза; для RAG сохраняйте права на источники и считайте найденные инструкции данными.
4. Сравните базовый вариант и кандидата на одних входах и при сопоставимых значимых настройках. Укажите срезы, знаменатели, сбои и отсутствующие результаты, неопределённость, задержку и стоимость; отделяйте качество поиска от качества сгенерированного ответа.
5. Для изменений в production определите совместимый комплект релиза, критерии продвижения, наблюдение с учётом задержки целевых значений и откат. Одна версия модели может не включать необходимые признаки, предобработку, промпты и состояние поиска.
6. Представьте измеренные результаты, случаи ошибок и ограничения. Выполняйте развёртывание и перенос данных в пределах существующих разрешений; исследовательский результат сам по себе не разрешает выпуск.

## Результаты

- Запрошенный эксперимент, реализация или оценка готовности
- Подтверждения оценки и ссылки на версии, при необходимости в отчёте об оценке или карточке модели
- Пояснения по развёртыванию, наблюдению и восстановлению при изменении поведения системы
- Отдельная сводка для передачи только при передаче работы или запросе сохраняемой сводки

Существующие шаблоны являются вспомогательными; для небольшой проверки отдельный файл отчёта не требуется.
