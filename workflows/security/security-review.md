# Workflow: Security Review

## Trigger

Use for architecture changes, public interfaces, cloud/platform changes, auth changes, sensitive data flows, dependency findings, or suspected incidents.

## Agents

- `security-architect`
- `threat-modeler`
- `appsec-engineer`
- `cloud-security-engineer`
- `devsecops-engineer`

## Steps

1. Identify assets, actors, data flows, and trust boundaries.
2. Review application, cloud, secrets, and supply chain risks.
3. Prioritize findings and mitigations.
4. Create remediation backlog and validation plan.
5. Update security notes and handoff.

## Outputs

- threat model
- security notes
- vulnerability triage when applicable
- handoff
