# Workflow: Implementation With Review

## Trigger

Use for backend, frontend, API, database, performance, or fullstack implementation.

## Agents

- implementation owner: `backend-engineer`, `frontend-engineer`, or `fullstack-engineer`
- reviewer: `code-reviewer` and relevant domain reviewers
- QA owner when behavior changes

## Steps

1. Read requirements, system analysis, and current code patterns.
2. Implement narrow behavior changes.
3. Update contracts and tests.
4. Run validation.
5. Review findings and fix blockers.
6. Write handoff.

## Outputs

- changed implementation
- updated tests/contracts
- validation result
- handoff
