# Подготовка данных для Linear

Определите исходный бэклог, целевую рабочую область и команду, формат результата и характер задачи: подготовка или выполнение. Сохраняйте локальные ID и существующее сопоставление с внешними ID.

## Существенные решения

- Определяйте команду, состояние процесса, исполнителя, метки, проект и цикл по предоставленным сопоставлениям или доступным данным на чтение. Не выводите внешний ID из отображаемого имени и не приравнивайте название роли к конкретному человеку.
- Сопоставляйте локальные статусы и приоритеты осознанно. Сохраняйте написание меток в целевой системе; соглашение о нижнем регистре не разрешает переименовывать существующие метки. Отсутствующие или неоднозначные сопоставления оставляйте нерешёнными.
- Классифицируйте пункты как создаваемые, обновляемые, неизменённые или заблокированные по постоянным ID и планируемым изменениям полей. Совпадение заголовков не означает тождество; не перезаписывайте удалённые изменения без сравнения текущего состояния.
- При неопределённом результате записи сначала найдите и сверьте существующий пункт, затем решайте, повторять ли создание. Фиксируйте подтверждённые внешние ID, чтобы повторный запуск обновлял те же объекты, а не создавал дубликаты.

## Результат и проверка

Верните сопоставление, предлагаемые действия, критерии приёмки и нерешённые вопросы. `templates/linear-export.yaml` — необязательная заготовка планирования, а не штатный файл импорта Linear или исполняемый запрос API. При отсутствии шаблона достаточно таблицы или структурированного ответа.

Запрос на подготовку завершается этим проверяемым результатом. Выполняйте синхронизацию в пределах запроса и правил проекта, учитывая уже данные разрешения. Перед использованием коннектора или API изучите фактическую схему и настройки целевой системы. Для прямой работы с API используйте актуальную [документацию Linear GraphQL](https://linear.app/developers/graphql).

Если запрошена запись, проверяйте её результат для каждого пункта. Явно сообщайте о частичном успехе и неопределённости; HTTP-ответ сам по себе не доказывает успех всех предложенных изменений.
