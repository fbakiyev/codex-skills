# Codex Skills & Tools

Практическая библиотека для разработки, платформенной инженерии, данных, ML, тестирования, безопасности, управления поставкой и офисной работы. Навыки задают конкретные решения и проверки, рабочие процессы связывают этапы, а локальные инструменты помогают выбрать, установить и проверить нужный набор.

Версия **1.2.0**: **54 навыка в 9 пакетах**, **64 описания ролей**, **16 рабочих процессов**, **34 шаблона** и **25 сценариев оценки**.

## Быстрый старт

Начните с результата и выберите несколько подходящих навыков. Например, для изменения серверного API пригодятся `api-design`, `backend-engineering` и `api-testing`; для анализа качества набора данных достаточно `data-quality`.

**Один навык через Codex.** Встроенному установщику можно дать конкретную папку GitHub:

```text
$skill-installer Установи навык api-design из https://github.com/fbakiyev/codex-skills/tree/main/skills/software-engineering/api-design
```

**Набор через локальные инструменты.** После клонирования репозитория подготовьте зависимости и посмотрите каталог:

```bash
git clone https://github.com/fbakiyev/codex-skills.git
cd codex-skills
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python scripts/manage_skills.py list --pack software-engineering
.venv/bin/python scripts/manage_skills.py show api-design
```

Для выбранных навыков укажите папку `.agents/skills` **целевого проекта**. В примере замените `/path/to/project`:

```bash
.venv/bin/python scripts/manage_skills.py install \
  --skill api-design --skill backend-engineering --skill api-testing \
  --dest /path/to/project/.agents/skills --dry-run
```

Проверьте план и повторите команду без `--dry-run` для копирования. Для установки целого пакета используйте, например, `--pack data-platform` вместо `--skill`. Можно указать несколько пакетов. Инструмент пропускает полностью совпадающие копии и останавливается при конфликте, сохраняя пользовательские изменения.

Для личного набора в разных проектах используется `~/.agents/skills/`. В CLI и IDE навык можно выбрать через `/skills` или упомянуть как `$api-design`; в ChatGPT доступный навык выбирается через `@`. Локальное копирование не подключает библиотеку к веб-интерфейсу: для распространения там нужен плагин. [Официальная документация навыков](https://learn.chatgpt.com/docs/build-skills).

## Как выполнять реальные задачи

Передайте исходники, конкретную цель, ограничения и ожидаемый результат. Названия навыков помогают выбрать процедуру, но не заменяют эти данные.

**Совместимое изменение API:**

```text
$api-design $backend-engineering $api-testing
Добавь повторяемое создание резервации. Старый клиент ожидает 201 и reservation_id.
Одинаковый запрос не должен повторно списывать остаток; тот же ключ с другими
данными должен давать конфликт. Изучи текущий код, реализуй и проверь изменение.
```

**Данные и отчётность:**

```text
$data-engineering $analytics-engineering $data-quality
После повторного запуска вырос итог отчёта. Проверь ключи, версии событий,
поздние исправления и соединение с историей клиентов. Покажи правильный итог
по предоставленной выборке и предложи воспроизводимое исправление.
```

**ML и RAG:**

```text
$rag-systems $model-evaluation
По этим документам и трассам ответ ссылается на старую политику. Раздели ошибки
поиска и генерации, проверь права на источники и предложи сопоставимую оценку
базового варианта и кандидата. Не объявляй улучшение по одному примеру.
```

Для задач из нескольких этапов используйте готовые процессы: [реализация и ревью](workflows/engineering/implementation-with-review.md), [платформа](workflows/xops/platform-delivery.md), [инцидент](workflows/xops/incident-response.md), [конвейер данных](workflows/data/data-pipeline-delivery.md), [ML-система](workflows/ml/ml-system-delivery.md), [стратегия тестирования](workflows/qa/test-strategy-to-automation.md), [проверка безопасности](workflows/security/security-review.md), [бэклог](workflows/agile/backlog-refinement.md), [офисный результат](workflows/office/office-deliverable.md).

Фактическую работу выполняют доступные инструменты среды: файловая система, Git, средства сборки и тестирования, SQL, облачные CLI, браузер или средства создания документов. Выбирайте их по проекту; перечень возможностей и зависимостей приведён в [руководстве по инструментам](docs/tooling.md#инструменты-для-предметной-работы).

## Что выполняют инструменты репозитория

| Инструмент | Практический результат |
| --- | --- |
| [manage_skills.py](scripts/manage_skills.py) | Поиск и просмотр навыков, подбор по пакету, копирование выбранных папок с проверкой конфликтов |
| [prepare_eval.py](scripts/prepare_eval.py) | Подготовка задания для модели отдельно от критериев оценки; многошаговые сценарии выдаются по шагам |
| [validate_repo.py](scripts/validate_repo.py) | Проверка структуры, YAML, версий, идентификаторов, ссылок ролей и признаков секретов |
| [inventory.py](scripts/inventory.py) | Сводка состава и сборка [полного каталога](docs/catalog.md) через `--markdown` |

Команды работают локально и не требуют API-ключа. Они не запускают модель, не подключают облако и не выполняют развёртывание. Python и зависимости нужны этим инструментам, а не для чтения текста отдельного навыка.

## Работа с современными моделями

Инструкции сохраняют существенные решения и проверки, не заставляя модель проходить весь процесс для любой задачи. Они учитывают рекомендации для GPT-6 Astra и GPT-5.6: точные условия применения, ограниченный набор инструментов, самостоятельное выполнение в пределах задачи и параллельность независимых частей. Обоснования, официальные источники и границы фактических проверок находятся в [руководстве по моделям](docs/model-guidance.md).

Устанавливайте нужный набор под область работы. Подключение всех 54 навыков не является обязательным условием: у больших каталогов часть описаний может сокращаться. Модель и её параметры выбираются в среде выполнения, а не в YAML-описаниях ролей. [Как загружаются навыки](https://learn.chatgpt.com/docs/build-skills).

Для проверки новой модели подготовьте предметный сценарий, например:

```bash
.venv/bin/python scripts/prepare_eval.py list --pack software-engineering
.venv/bin/python scripts/prepare_eval.py prepare software-engineering/api-change \
  --output /tmp/api-change-eval
```

Передайте проверяемой модели только `task.md` текущего шага. `criteria.md` и `manifest.json` оставьте проверяющему. Сопоставляйте результаты на одинаковых входных данных и инструментах; учитывайте ошибки, время и стоимость. Экспорт задания не означает его успешное выполнение. Подробности и многократные прогоны описаны в [руководстве по инструментам](docs/tooling.md#проверка-поведения).

## Устройство и соглашения

`skills/` содержит устанавливаемые инструкции, `agents/` — описания 64 ролей, `workflows/` — последовательности действий, `templates/` — необязательные заготовки. `codex-skills.yaml` задаёт состав пакетов, а `evals/cases.yaml` описывает подготовку проверочных заданий.

Роли помогают распределить обязанности и выбрать навыки через поле `skills`. Их YAML не является конфигурацией встроенных исполнителей Codex и сам не запускает параллельную работу. Для обычного завершения не нужны все перечисленные `artifacts`; отдельная передача определяется `handoff.when` и задачей.

Человекочитаемые инструкции и документация написаны по-русски. Идентификаторы, пути, ключи YAML, код, названия продуктов и буквальные тестовые значения сохраняются. Язык результата задаёт пользователь. Библиотека универсальна: место хранения, доступы, разрешения на изменения и правила публикации определяет конкретный проект.

## Проверка и сопровождение

Из корня репозитория, после установки зависимостей:

```bash
.venv/bin/python scripts/validate_repo.py
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python scripts/inventory.py
.venv/bin/python scripts/inventory.py --markdown > docs/catalog.md
```

Проверка структуры не доказывает правильное поведение модели или доступность сервисов. В репозитории 25 исходных предметных сценариев; применимые примеры и критерии используйте при изменении навыков. Тесты инструментов проверяют их реальную локальную работу в отдельных временных каталогах.

В 1.2.0 содержательно переработаны 44 профильных навыка, унифицирован русский язык и добавлены инструменты выбора, установки и подготовки оценок. Офисный пакет дополняет инженерные области. Инструкция обновления установленных копий и прежние переименования папок находятся в [руководстве](docs/tooling.md#обновление).
