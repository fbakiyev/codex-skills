# Codex Skills

Библиотека навыков, описаний ролей и шаблонов для инженерной и обычной офисной работы. Выбирайте навык по нужному результату: документу, расчёту, письму, презентации или изменению системы.

## Офисные задачи

Для повседневной работы достаточно пакета `office-work`. Он не требует знакомства с инженерными процессами.

| Задача | Навык | Пример запроса |
| --- | --- | --- |
| Подготовить или обновить документ | `prepare-office-documents` | Обнови инструкцию по этим трём изменениям, сохрани исключения и структуру таблиц |
| Обработать таблицу | `work-with-office-sheets` | Сведи данные подразделений, проверь формулы и покажи общий процент выполнения |
| Подготовить встречу или протокол | `prepare-and-close-meetings` | Из заметок выдели решения, поручения и открытые вопросы |
| Написать деловое письмо | `draft-business-correspondence` | Подготовь ответ поставщику с учётом последнего сообщения и условий оплаты |
| Собрать презентацию | `prepare-office-presentations` | Сделай презентацию на пять минут по результатам пилота, сохрани ограничения данных |

Укажите источники, аудиторию и желаемый формат, если они уже известны. Для простой задачи достаточно одного запроса. Навык использует доступные средства работы с файлами; сам по себе он не устанавливает редактор, не подключает почту и не выдаёт доступ к облачным документам.

## Подключение

Папки `skills/<pack>/<name>/` содержат устанавливаемые навыки. Файлы `agents/**/*.yaml` описывают роли этой библиотеки: они не являются конфигурацией встроенных исполнителей Codex и сами никого не запускают. `codex-skills.yaml` служит каталогом для локальных проверок.

Для локального использования скопируйте нужную папку навыка целиком, включая её `references/` и `assets/`, в `.agents/skills/<name>/` целевого проекта или `~/.agents/skills/<name>/` для личного использования. Перед копированием проверьте, нет ли уже навыка с таким именем. Не заменяйте существующую версию без сравнения. Эти пути и способы вызова описаны в [документации навыков](https://learn.chatgpt.com/docs/build-skills).

В CLI и IDE навык можно выбрать через `/skills` или указать `$prepare-office-documents` в запросе. В интерфейсе ChatGPT доступен выбор через `@`. Не обязательно устанавливать всю библиотеку: короткий набор нужных навыков проще выбирать и сопровождать. Если обновление не появилось, перезапустите приложение. [Способы вызова](https://learn.chatgpt.com/docs/build-skills#how-chatgpt-and-codex-use-skills).

Офисные навыки самодостаточны. Общие шаблоны из `templates/` необязательны. Для инженерных сценариев, ссылающихся на общие шаблоны, держите эту копию репозитория доступной и укажите её расположение в задаче.

## Как устроена работа

Начинайте с результата и критериев его готовности. Исполнитель завершает разрешённую работу, уточняет существенные пробелы и проверяет то, что могло измениться. Масштаб проверки зависит от задачи: для письма важны факты и условия, для таблицы ещё формулы, для файла ещё его открытие и оформление.

Спринт нужен при работе по спринтам. Отдельный handoff нужен при передаче работы или запросе на сохраняемую сводку. Архитектурные решения, runbook и карты доступа добавляются при соответствующих изменениях системы. Простая правка не требует всех этих документов. Поля `artifacts` перечисляют применимые виды результатов, а `handoff.when` описывает условие отдельной передачи.

Запрос на черновик не означает разрешение отправить письмо. Уже выданное разрешение учитывается вместе с правилами рабочей среды. Git-публикация, изменение общих документов и установка навыков не выполняются автоматически при каждом завершении задачи.

Место хранения контекста и документов выбирает пользователь или команда: локальная папка, база знаний либо репозиторий. Библиотека не задаёт личные пути и корпоративную политику. Перед сохранением учитывайте видимость места назначения; частные данные не должны попадать в публичные материалы. Секреты остаются в защищённом хранилище.

## Совместимость с моделями

В версии `1.1.0` уточнены границы самостоятельной работы, убраны обязательные спринты и handoff для каждой мелкой задачи, сужены триггеры основных навыков. Причины и источники для GPT-6 Astra и GPT-5.6 собраны в [рекомендациях по моделям](docs/model-guidance.md).

Навыки не закрепляют модель и не меняют настройки среды. Сравнивайте варианты на одинаковых заданиях из `evals/sample-tasks/`, отдельно оценивая качество, время и стоимость.

При обновлении по пути из GitHub учтите три переименования папок: `agile-delivery/review-retro` → `agile-delivery/sprint-review-retro`, `xops-platform/platform-design` → `xops-platform/xops-platform-design`, `data-platform/orchestration` → `data-platform/data-orchestration` внутри `skills/`. Имена самих навыков сохранены. Проверка создания репозитория перенесена в `evals/sample-tasks/core/repository-foundation.md`.

## Разработка и проверка

Для скриптов требуется Python 3.9 или новее.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python scripts/validate_repo.py
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python scripts/inventory.py
```

Валидатор проверяет YAML, версии, состав пакетов, уникальность идентификаторов, ссылки на навыки и шаблоны, а также очевидные секреты без вывода их значений. Это проверка структуры, а не доказательство правильного поведения модели. Сценарии `evals/sample-tasks/office/` содержат исходные данные и критерии для проверки результата в используемой среде.

Меняйте инструкцию при подтверждённой повторяемой проблеме и в рамках задачи по сопровождению библиотеки. Для публикации сначала подготовьте итоговое изменение, выполните проверки и получите требуемое правилами рабочей среды разрешение.
